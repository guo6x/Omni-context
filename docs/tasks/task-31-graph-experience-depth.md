# Task 31: 图谱体验深化（聚焦动画 + 时间维度可视化）

## 背景

[[task-21-graph-visual-triple]] 把节点大小 / 关系线颜色 / Legend 三件套做完后，图谱基础视觉很扎实了。还差两个**体验维度**的提升：

1. **聚焦动画太弱**：Ctrl+K 搜到节点跳过去，只是白色边框 + dimmed 其他节点。用户得花两秒才能找到"哦原来在这里"
2. **没有时间维度**：用户看不出"哪些节点是今天新增的"、"哪些是半年前的老笔记"。图谱看起来是静态快照而不是生长中的记忆

## 目标

### A. 节点聚焦脉冲动画

- 当 `focusEntityId` 改变 → 找到对应节点 → 触发一个"扫光 + 涟漪"动画
- 实现：节点周围画一个 expanding circle（从节点中心向外辐射 + 透明度衰减），同时节点自身做一次缩放脉冲（1x → 1.4x → 1x，500ms）
- 动画完成后回到 selected 静态状态（白色边框 + glow）
- 视觉目标：用户余光也能看到"那个点动了"，1 秒内能定位

### B. 时间维度（节点创建时间着色或叠层）

两种方案二选一（执行 AI 自己评估哪种实现更稳）：

**方案 1（推荐）：发光环表示新鲜度**
- 实体的 `created_at` 越新 → 节点外圈加一个 cyan glow ring（亮度按 freshness 衰减）
- 7 天内创建的节点 ring 最亮，30 天内中等亮度，更老的没有 ring
- 不改变节点颜色（颜色继续表示 type），只在最外层加一圈

**方案 2：时间 filter slider**
- Legend 下方加个 slider "显示最近: [今天] [7 天] [30 天] [全部]"
- 选了之后老节点 dimmed 透明度更低（30%）

方案 1 信息密度更高、不需要交互，推荐。方案 2 适合"我只想看最近的"使用场景。

## 涉及文件

- `desktop-daemon/src/components/GraphViewer.tsx`
  - **聚焦动画**：
    - 监听 `focusEntityId` 变化，启动一个 RAF 循环（`requestAnimationFrame`）追踪 0-500ms 的动画进度
    - 在 `nodeCanvasObject` 里读取当前动画进度 → 多画一个 expanding circle + 调整 node radius
    - 500ms 后清除动画状态
  - **时间维度（方案 1）**：
    - 节点数据准备阶段计算每个节点的 `freshness`（0-1，今天 = 1，30+ 天 = 0）
    - `nodeCanvasObject` 里如果 freshness > 0，多画一圈 cyan ring（透明度 = freshness * 0.6）
- `desktop-daemon/src/locales/zh.ts` + `en.ts`
  - 如果做了方案 2 slider 加 i18n key

## 约束

- **聚焦动画一次性**——同一节点反复聚焦不要叠加多个 ripple
- 动画必须能被打断（用户在动画进行中又搜了别的节点，立刻切到新节点的动画）
- 大图谱（1000+ 节点）时聚焦动画不能让全图重绘卡顿——只重绘聚焦节点周围 200px 内的节点
- 时间维度的 freshness ring **跟 type 颜色区分明显**（cyan 跟 type palette 不冲突）
- 不要做"时间动画播放"（从老到新一个个出现）——那是另一回事
- 不引入新的动画库（GSAP / framer-motion 之类）——RAF + state 就够

## 验收标准

1. ✅ Ctrl+K 搜个节点 → 跳过去后看到明显"脉冲 + 涟漪"动画
2. ✅ 连续搜不同节点 → 旧动画立刻被新动画取代，不叠加
3. ✅ 用 demo 数据加载示例图谱 → 最近创建的节点周围有 cyan ring，老的没有
4. ✅ Ring 亮度按时间衰减明显
5. ✅ 1000 节点的图谱跑动画不掉帧（用 demo 多加载几次复制）
6. ✅ `npm run build` 通过

## 不要做的事

- 不要为了"酷"加更多动画（节点 idle 时呼吸效果之类）——会让长时间使用的用户疲劳
- 不要把动画做成可配置——固定 500ms / 固定颜色就好
- 不要把时间维度跟 type 颜色搅在一起（type 颜色保留为主色）
- 不要做"3D 模式下的时间维度可视化"——本期仅 2D 模式
