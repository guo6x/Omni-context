# Omni-Context Alpha：一页试用流程

这次试用只需要一份你愿意分享给所选模型的**不敏感资料**。你可以随时跳过屏幕/剪贴板
捕获，也可以拒绝提供任何个人资料。试用的目标是确认“它能否接着我之前的事情思考”，
不是证明 AI 永远正确。当前尚未批准外部试用；只有
[交付记录](2026-10-25-goal24-readiness.md) 明确为 `ALPHA_USER_TRIAL_READY` 且邀请方
批准后，才执行下面的安装步骤。

## 15 分钟核心旅程

1. **安装并启动。** 只使用交付负责人明确批准并提供来源 commit 与 SHA-256 的 Alpha
   安装包，先按 [Windows 安装说明](INSTALL-WINDOWS.md) 核对来源、未签名风险和校验值。
   已有 Omni-Context 的电脑不要自行并排安装或卸载旧版。首次启动保留捕获暂停，
   先看懂隐私说明；不需要安装 Node.js、Rust 或 Git。
2. **选模型。** 优先使用本地模型。若选择云端模型，请确认相关资料片段会发送给该提供方，
   可能产生费用；只选择你愿意发送的资料。
3. **导入一份熟悉的记录。** 选择一份聊天导出、Markdown、TXT 或 PDF，内容可以是已公开的
   项目笔记或虚构测试资料。等待导入回执，确认保存数量和是否有未完成任务。
4. **检查导入结果。** 不要把“已抽取”当作“新增记忆”，也不要在状态不确定时重复上传。
   失败时使用原任务恢复入口或重试按钮。
5. **提一个你知道部分答案的问题。** 在 Ask 输入例如：

   - “我之前为什么决定做这个项目？”
   - “我最近的目标发生了哪些变化？”
   - “你这个判断依据的是哪些资料？”
6. **看回答依据。** 展开来源，确认它们确实来自刚才的资料。来源 ID 是可追溯线索，
   不是独立事实核验；没有证据时，回答应明确说“不知道”或请求澄清。
7. **继续问一轮。** 追问“哪些地方仍不确定？”或“还有相反的证据吗？”，观察回答是否
   保持上下文，而不是凭空补写经历。
8. **保存一个重要结论或决定。** 先修改/确认“我的最终决定”，再显式点击保存。原问题、
   AI 分析、来源和你确认的决定应分开显示；保存决定不会授权 Agent 执行外部操作。
9. **确认回执。** 看到“已保存到本机”后再离开。若回执丢失或显示“待核对”，先打开
   决策日志确认，之后才决定是否对同一条记录安全重试。
10. **关闭再打开。** 从托盘选择“退出”或使用应用的完全退出选项；重新打开后点击
    Ask 的“继续讨论”，找到原问题并追问。到“历程 → 决策复盘”查看刚才的决定，可选地
    记录后来实际发生的结果。

## 你应该看到什么

- 捕获默认暂停；不启用它也能完成导入、Ask 和决定保存。
- 敏感应用名单只检查前台应用，不会遮住主屏幕截图中的后台窗口或通知，也无法判断剪贴板内容来源；若画面或剪贴板可能包含不想发送的内容，请保持暂停。
- 隐私设置变更需要等本机确认；确认前不要假定暂停或恢复已经生效，已开始的捕获/提交可能仍在收尾。确认暂停后才会拒绝新的捕获操作。
- 回答显示来源与不确定性；找不到资料时不会伪造记忆。
- 原始资料是来源，不一定是已核实事实；AI 分析、你确认的事实、你作出的决定和后来发生的结果应分开判断。
- 关闭重开后，已确认保存的讨论和决定仍可找到；临时未确认的写入不保证存在。
- 云端模型只接收当前处理所需的请求，费用和数据处理由所选提供方决定。

## 任何时候都可以停止

不想继续时退出应用即可。卸载前先在“设置 → 数据管理”导出备份；备份可能含完整
私人资料，需像原始资料一样保护。不要把完整数据库、完整聊天记录、日志、token 或
API key 上传给支持者。可在本地填写 [试用反馈表](TRIAL-FEEDBACK.md) 或
[问题模板](ISSUE-TEMPLATE.md)，由你自行决定是否通过与邀请方既有、双方确认的私人渠道
发送。无需专用邮箱，也不自动上传任何资料；公开 Issue 只适合不含个人资料的最小复现。
