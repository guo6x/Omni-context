# Windows Alpha 安装与隐私说明

这是一份给第一批知情试用者的安装说明。它只适用于 Omni-Context 的 Windows
x64 **NSIS** 候选包；本轮不把 MSI 当作交付格式。候选包不是公开正式版，也不应在
没有核对来源和校验值的情况下转发。截至 2026-10-25，本轮尚无通过真实安装版原生隐私
验收的试用包，**不要安装、转发或邀请外部用户使用**；只有后续明确批准的 Alpha 发布记录
才会解除这一限制。

## 先核对候选包

只有在交付负责人提供带精确版本、来源 commit 与 SHA-256 的专用 Alpha 发布记录后，才从
项目官方 GitHub Releases 页面下载对应资产：
<https://github.com/guo6x/Omni-context/releases>。当前不得把 `Releases/latest` 中的旧版或
名称相似的文件当作本轮候选，也不要使用聊天附件、网盘转存或陌生镜像中的同名文件。

候选安装器的文件名形如：

```text
Omni-Context_<version>_x64-setup.exe
```

交付负责人必须在随包的 release 记录中绑定下面四项；缺少任一项就先不要安装或分发：

| 项目 | 以什么为准 |
| --- | --- |
| 应用版本 | 安装器文件名与 `desktop-daemon/src-tauri/tauri.conf.json` 的版本 |
| 构建来源 | GitHub 仓库 `guo6x/Omni-context` 的精确 commit SHA |
| 安装包完整性 | 官方 release 记录中的 SHA-256 |
| 验证结果 | 本候选的隔离安装、启动、退出和卸载记录；不得用旧包记录代替 |

下载后在 PowerShell 中计算校验值（把路径替换为实际文件）：

```powershell
Get-FileHash .\Omni-Context_<version>_x64-setup.exe -Algorithm SHA256
```

检查签名状态：

```powershell
Get-AuthenticodeSignature .\Omni-Context_<version>_x64-setup.exe |
  Select-Object Status, StatusMessage, SignerCertificate
```

此前记录的旧版 `Omni-Context_0.1.1_x64-setup.exe` 签名检查结果为 `NotSigned`：它没有
Authenticode 发布者签名，不能宣称已获 Windows 发布者信任。该文件是源码仍在变化期间的
历史构建；截至 2026-10-25，当前 worktree 和仓库根目录的预期位置均没有它，也没有新候选，
**当前不要安装、转发或邀请外部用户试用**。后续若获准的
Alpha 候选仍为 `NotSigned`，Windows 可能显示“未知发布者”或 SmartScreen 警告；SHA-256
只能核对文件是否与官方记录一致，不能替代签名或证明发布者身份、软件安全。

只有交付负责人明确批准某个候选并提供匹配的官方 release 记录后，才考虑试用；SHA-256
必须完全一致。不要为了安装关闭 Defender、SmartScreen、实时防护或其他系统安全设置，
也不要绕过安全产品的阻止。若来源不明、hash 不一致、Defender/SmartScreen 阻止运行，或
出现与记录不符的行为，请取消并通过反馈模板报告。

## 安装与首次启动

1. 关闭同一用户下已经运行的旧 Omni-Context，再双击核对过的 NSIS 安装器。不要以
   管理员身份运行，除非 Windows 明确要求并且你知道改变了什么。
2. 记录安装器显示的安装路径。按当前 Tauri NSIS 默认配置，预期是当前用户下的
   `%LOCALAPPDATA%\Omni-Context`；**本轮尚未真实安装核验**，不能把预期当作已确认结果。
   以安装器实际显示的路径为准，并在候选验收记录中保存该路径。
3. 安装资源与个人数据分开：安装器更新的是安装路径，不会把
   `%LOCALAPPDATA%\omni-context\data` 当作安装资源覆盖。首次在已有资料的机器上
   试用仍应先导出一份备份，且不要同时运行两个版本。
4. 安装完成后从开始菜单启动 Omni-Context。试用者不需要预先安装 Rust、Git 或
   Node.js；候选交付记录必须确认内嵌 Brain/Node 运行时确实存在。若启动页要求
   另装运行时，请停止试用并报告“候选打包不完整”。
5. 首次启动时先保留“暂停捕获”。屏幕和剪贴板捕获不是完成导入、Ask 或决定记录的
   必要条件；只有在隐私设置中明确确认后才考虑启用。
   敏感应用名单只在该应用成为前台窗口时阻止沉淀，不会从截图中遮住后台窗口、弹窗或
   通知；屏幕捕获会包含主显示器整幅画面，剪贴板捕获读取系统当前剪贴板且无法判断内容
   来源。若屏幕或剪贴板可能含不想处理/发送的内容，请保持暂停。
6. 选择本地模型（例如本机 Ollama）或远程模型。远程模型会收到完成当前操作所需的
   资料片段，并可能产生费用；不要把 API key 写进截图、问题单或聊天记录。

## Windows 上的数据、日志和配置位置

Omni-Context 默认把 Brain 数据留在本机，但“默认本机”不等于“任何模式都不会联网”。
若配置远程模型，相关请求可能离开设备；完整数据库不会因为打开 Ask 而自动上传。

| 内容 | 默认位置或边界 |
| --- | --- |
| 记忆数据库、导入恢复记录 | `%LOCALAPPDATA%\omni-context\data\omni-context.db`；同目录可能有 SQLite WAL/SHM 文件和 `import-recovery.json`。失败导入为支持恢复，可能在数据库的失败任务记录中保留来源标题和文本 |
| Brain 日志 | `%LOCALAPPDATA%\omni-context\logs\brain-server.log`（最多轮转三份，每份约 5 MB）。日志可能包含错误摘要、依赖诊断文本；旧版本也可能记录过导入标题、洞见标题或查询文本。新代码移除了已确认的原始查询/标题日志点，但不要把整份日志视为已脱敏 |
| 本地连接 token、配对及运行期文件 | `%LOCALAPPDATA%\omni-context\`；不要分享 `local-token.txt`、配对码或控制会话文件 |
| 桌面偏好、语言、模型设置（包括用户填写的服务商 API key）、隐私设置 | Tauri/WebView2 的用户配置存储，由应用管理；当前不能宣称 API key 受 Windows 凭据保管库加密。Tauri app data 位于 `%APPDATA%\com.omni-context.app\` 和/或 `%LOCALAPPDATA%\com.omni-context.app\` 下，WebView2 子目录会随版本变化。卸载器若提供“删除 app data”勾选项，只清理这两个 app-id 目录范围；不要手动编辑或整目录上传 |
| 安装文件和内嵌 Brain | 安装器选择的安装路径；卸载安装器只处理安装内容，不应被当作个人数据清理工具 |

若上次隐私设置中断，Brain 数据目录还可能有 `capture-policy-revoked` 状态文件。它只表示需要用户重新确认隐私设置，不包含资料或捕获内容；它会随 Brain 数据保留，直到用户完成明确的隐私设置恢复。

设置页的“打开数据目录”和“打开日志目录”按钮是最可靠的入口。当前没有自动生成的
反馈压缩包或上传功能；发送日志前应逐行检查并脱敏。复制数据库前先
完全退出 Omni-Context，等待 Brain 进程结束；运行中复制 SQLite 文件可能得到不完整的
备份。不要把 token、完整数据库或完整聊天记录发给试用支持者。

## 备份、导出和恢复

1. 打开“设置 → 数据管理”，使用“导出 JSON”或“导出 Obsidian Vault”。导出内容可能
   包含完整的实体、关系、原始资料片段、决定和通知，按个人敏感数据处理；把备份放在
   受密码保护的磁盘或加密存储中。
2. 需要迁移或故障恢复时，使用“从备份恢复”。“合并”会尽量保留现有数据；“替换”
   会清空当前数据库后导入，属于不可逆操作。执行替换前先做第二份备份。
3. 备份导出是本机操作，不代表远程云端备份；项目当前不承诺自动异地备份、跨设备同步
   或硬盘故障后的恢复。

## 正常退出、卸载和停止试用

- 需要退出时，在托盘菜单选择“退出 Omni-Context”，或在设置中选择“完全退出应用”。
  关闭窗口若设为“最小化到托盘”，并不等于停止；确认托盘图标消失或应用报告 Brain
  已停止后再关机、复制数据库或卸载。
- 通过“Windows 设置 → 应用 → 已安装的应用”卸载 Omni-Context，或运行安装目录中
  的卸载器。卸载器可能询问是否删除 app data；勾选后的清理范围是 Tauri app-id 目录
  `%APPDATA%\com.omni-context.app\` 与 `%LOCALAPPDATA%\com.omni-context.app\`，不是
  Brain 的个人数据目录。
- 卸载会移除安装内容；Brain 数据在独立位置：数据库和导入恢复记录位于
  `%LOCALAPPDATA%\omni-context\data\`，日志位于 `%LOCALAPPDATA%\omni-context\logs\`，
  token/配对及运行期文件位于 `%LOCALAPPDATA%\omni-context\`。这些目录不会被上述
  app-data 勾选项清除，卸载后可能保留。卸载前务必导出并核对备份；确认不再试用后，
  才由用户自行决定是否删除这些目录。删除后无法从 Omni-Context 本地恢复。
- 卸载后在任务管理器确认没有遗留 `Omni-Context.exe` 或内嵌 Brain/Node 进程。发现
  进程仍在运行时，先重新启动应用并从托盘退出；不要直接结束陌生进程。

## 出错时怎么做

先记录版本、Windows 版本、安装器 SHA-256、重现步骤和预期/实际结果；再看设置中的
Brain 状态和日志目录。当前尚未配置私下反馈地址或上传入口；只有在邀请方另行提供经过
确认的联系渠道后，才可选择提交同意过的脱敏截图或少量脱敏日志行。删除聊天正文、个人
资料、API key、token、配对码和完整数据库；不要把敏感附件发到公开 GitHub issue。导入显示“状态待核对”时，先查看记忆库和
原任务恢复入口，不要盲目再次上传同一文件。

隐私策略同步失败、暂停状态与捕获行为不一致、或未知前台窗口仍然被捕获时，立即停止
捕获、关闭试用并按问题模板标记为高严重度；不要为了继续使用而放宽策略。

如果设置页显示“捕获已撤销”，说明此前的隐私设置没有可靠保存，旧的捕获授权不会在下次启动时自动恢复。先使用“保存并保持暂停”，等状态确认后，再通过暂停开关单独选择是否恢复捕获。若界面提示“无法确认原生捕获已停止”，不要重试恢复；使用“退出 Omni-Context”并报告问题。
