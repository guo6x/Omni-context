# 用一份记录体验 Omni Alpha

本指南面向个人用户：先用一份不敏感、自己熟悉的资料，验证 Omni 是否能帮你接着上次的事思考。它不是自主执行授权，也不是已核实事实的保证。

## 第一次使用

1. 在首次引导中选择模型并测试连接。本地 Ollama 需要你已经安装并运行对应模型；Omni 不会替你购买或开通 API。选择云端模型意味着相关资料片段会交给该提供方处理，并可能产生该服务的费用。
2. 导入一份熟悉的聊天记录或文档。先看导入回执：保存数量、未完成部分、原任务恢复入口。不要把“已抽取”当作“净新增”，也不要在结果未知时反复上传。
3. 点击“用这些记忆提问”，问一个你知道部分答案的问题，例如“我之前为什么决定做这个项目？”。准备问题不会自动调用模型，仍需你发送。
4. 核对回答里的来源。来源详情按 ID 读取本机记忆条目；AI 抽取条目不等于独立核实过的原文。证据不足时不要把建议当作记忆事实。
5. 当回答出现“记录我的决定”时，先修改或确认“我的最终决定”，再显式保存。原问题、AI 分析、来源和你确认的决定分别保留。这个操作不会授予 Agent 执行权限，也不代表结果已发生。
6. 等到“已保存到本机”回执再退出。回执表示本机 Brain 已确认讨论写入，不是异地备份保证。未确认时先重试；不能确定的决定写入不会自动重发，应打开决策日志核对。
7. 以后打开“历程 → 决策复盘”，展开该决定即可记录后来发生的结果。它是你自己的复盘日志，不是独立核验，也不会自动改变系统原则；如果结果保存回执不确定，可在当前窗口用同一条记录“安全重试”。若已关闭软件，先重新打开决策日志检查是否已保存，再决定是否重新记录。

## 第二次使用

打开 Omni → 点击 Ask 输入栏的“继续讨论” → 选择原问题。可继续追问、重新核对来源，并在“历程”的决策日志中查看或记录后续结果。个人结果记录仍是用户日志，不是 CP8 外部验证。

历史列表读取失败时会显示错误和重试入口，不能把它当作“没有历史”。操作系统强制终止、磁盘故障或未收到保存回执时，不能保证最新进度已落盘。

## 换一个 AI 客户端

在 MCP 设置中配置受支持的客户端，并在那个客户端实际查询一条已保存的记忆或决定。界面“已配置”只说明发现了配置，不代表已经握手成功。不同客户端不一定共享 Ask 的完整聊天记录；完整讨论仍在 Omni 的“继续讨论”中。

## 保持安静和隐私

捕获默认暂停，不必启用屏幕/剪贴板捕获也能使用导入、Ask 和个人决策。到设置的隐私页管理暂停、敏感应用排除与数据。原生捕获入口会检查已确认策略和前台应用；未知策略或无法核验的前台应用会被拒绝。

若隐私页提示同步失败，先不要触发捕获，重试或关闭并重新启动 Omni。原生进程保留上次确认的运行期策略；若整个 IPC 通道不可用，不能承诺新设置已经生效。
