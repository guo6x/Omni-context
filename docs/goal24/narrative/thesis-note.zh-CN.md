# 长期 Agent 不只需要记忆，更需要可被现实纠错的决策控制

**为什么长期运行的 Agent 需要"现实不符时可以重新打开"的决策。**

> 状态：Narrative 论点注记（N1）。本文论证的是品类级论点，不是任何具体产品的
> capability 声明。文章必须独立成立：即使删去品牌名，每个论点也应依然成立。

---

## 1. 问题：Agent 会行动，但光有记忆拦不住一次错误行动

给 AI Agent 做记忆的系统已经越来越好。一个 Agent 可以累积它读过的、说过的、
决定过的内容，并且越来越精准地回忆。

但长期 Agent 的主要失败方式，并不是"它忘了什么"。
而是它**行动**了——依据的是过期的、片面的、无法验证的、或者仅仅是说得很有信心的
信息——而整个链路里没有任何一环能够拒绝、核验或纠正这次行动。

三个观察：

1. **Agent 会行动。** 有价值的长期 Agent 都会在现实世界里做事：写代码、开 issue、
   改配置、跑命令、消耗资源。
2. **记忆不是证据。** Agent 记住的任何东西，都只是"某个时刻、来自某个来源、
   带有某种不确定性的关于世界的陈述"。单靠回忆，分不清一个经过验证的事实
   和一个流畅的猜测。
3. **工具成功不等于结果真实。** 进程退出码为 0，只是关于进程的事实，不是关于
   世界的事实。它不代表你想要的改变发生了，也不代表没发生你不想要的改变。

只记得更多、或只观察得更多的系统，永远补不上这个缺口。
缺的是**决策控制**：行动前先做证据资格，把行动绑定到为之负责的那次决策上，
行动后再核验，现实不符时重新打开那次决策。

---

## 2. 判断闭环的四个动作

### 行动前先有资格（QUALIFY BEFORE）—— 记忆不等于合格证据

Agent 依据记忆行动之前，这些信息必须先经过资格审定：它来自哪里、有多新、
是否曾被验证、以及它是否仍然适用于**此刻**即将使用的那项能力。

资格审定是一道**闸门**，不是检索功能。检索回答"Agent 知道什么"；
资格审定回答"这些信息现在还能不能信、够不够格支持行动"。
一条来源不明却检索得分很高的内容不是证据——只是建议。

### 绑定（BIND）—— 执行必须绑定到为它负责的那次精确决策

"允许跑点什么"不是决策。决策是具体的：
**这个**能力、**这份**输入、**这组**证据、**这个**预期改变、**这种**验证方法。

执行必须绑定到那次精确的决策。如果实际运行的动作不是被批准的那个动作——
输入、证据或预期在"批准"与"执行"之间发生漂移——事后补多少日志都补不回来。
绑定，让"已批准"三个字真正有意义。

### 行动后读回现实（READ BACK AFTER）—— 退出码 0 不等于成功

Agent 行动之后，必须有人**重新观察现实**——通过一条独立于该行动本身的通道——
把观察到的现实与当初支撑决策的预期做比较。

进程退出 0 ≠ 语义成功 ≠ 外部状态真的变了 ≠ 用户预期的结果被验证。

这是四个不同的问题，而 Agent 自己的汇报不是答案。
验证是观察行为，不是成功宣言。

### 重开决策（REOPEN）—— 现实不符时，重新打开那次决策

当观察到的现实与当初的预期矛盾时，正确的反应不是记一条错误日志了事。
错误是症状；需要修正的单位是那次**决策**——它的证据错了、预期错了，
或者世界在它之下变了。

重新打开那次决策：重查证据、修正预期，然后要么重新决策，要么记录下
"为什么这个决策仍然成立"。长期 Agent 最该拥有的历史，
是那些被现实证明为错的决策——因为只有这份历史才真正教人成长。

---

## 3. 位置：接口与执行运行时之间缺失的那一层

Agent 接口正在走向标准化：越来越多的 Agent 用同样的协议形状提问、调用工具。
执行运行时也在走向标准化：越来越多的环境可以稳定地拉起进程、运行工具。

仍然缺失的，是两者之间的**判断层**——

它能在证据不足时**拒绝行动**，

能把执行**绑定到**为之负责的那次决策上，

能在现实不符时**重新打开那次决策**。

这一层不是更好的提示词，不是更大的上下文窗口，也不是另一块可观测性面板。
它是控制：Agent 的意图在这里变成一次经过检查、绑定、可验证的决策——或者被拒绝。

---

## 4. 结论

Agent 产品的长期护城河，不是记忆库的大小。
而是这个闭环：

> **行动前先有资格。绑定。行动后读回。现实不符就重开。**

真正属于你的，是一部会被现实纠错的判断史。
