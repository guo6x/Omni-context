# 04 — 离线检索层指标（不调用 Answer/Judge）

## 1. 两个互补口径

正式 brain.db 未保留，候选池未落盘，因此建立两个可审计口径：

**口径 A：正式系统实测（results.jsonl 反推）** —— 唯一能反映"系统真实检索输出"的口径：
- Final Context Recall@30(any) = **0.483**，(full) = 0.389（149 可映射可答题；映射方法与置信度见报告 03 §1）
- Extraction Coverage（代理下界）= 0.785
- Candidate Pool / Reranker 中间层 Recall：**无法测量**（未落盘）——这是评测基建缺口，Candidate v2 应把候选池快照写进 results.jsonl。

**口径 B：对话级理想底座测评（`evidence/retrieval-testbed.mjs`）** —— 把 LoCoMo Conv1 的 419 条对话轮（带 session 时间戳前缀）作为 passage 库、150 道有 evidence 的可答题作为 query、官方 dia_id 作为 gold，用与生产完全相同的 transformers.js 管线嵌入。该口径把 embedding 模型从抽取/序列化/挂载问题中隔离出来，用于模型对比与消融（报告 05/06 使用同一口径）。

Gold→passage 映射为精确 dia_id 对齐（无歧义，置信度=1.0）。150/152 可答题有非空 evidence；2 题无法映射，如实剔除。

## 3. 关键读数

1. **系统损失 > 模型损失**：同一个 e5-small 无前缀，在理想文本底座上 R@10=0.613，而正式系统最终上下文命中只有 0.483。即：即使不换模型、不改用法，仅把检索底座从"实体向量 + 非语义 assertion 挂载"换成"对事实文本直接做向量检索"，就能拿回约 13 个百分点的上下文命中率。
2. **前缀修复对排序端收益显著**（R@1 +29% 相对、MRR +14% 相对、temporal R@10 0.757→0.865），对深召回（R@20）收益小——与 E5 论文的行为一致。
3. **multi_hop 是 embedding 的天然弱项**（R-full@10 只有 0.091）：多跳需要 2+ 条分散 evidence 同时进上下文，单向量检索不解决，需要图扩展/多查询分解，与模型大小关系不大。
4. **Temporal Current vs Historical/As-of**：对话数据均为 2023 年历史事实，本测评不含时间过滤层，正式系统中的 as-of 语义损失计入口径 A 的 CDE 类（报告 03）。

## 4. Assertion/Entity Recall 说明

任务书要求的 Assertion Recall / Entity Recall / Candidate Pool Recall / Reranker Recall 需要正式库与候选池快照，均不可测（正式库缺失）。已用口径 A 的 Final Context Recall 与 Extraction Coverage 给出可测的上下游夹逼，中间层的进一步细分列为 Candidate v2 的评测基建需求。
